1. Executive Summary

This report presents the technical implementation of the data engineering architecture and automated ingestion/transformation pipeline developed for Workshop No. 2 in the Data Analysis Programming course. Building directly upon the data source contracts and empirical profiling formalized in Workshop No. 1, this milestone moves from conceptual design into a fully functional, containerized system powered by Apache Airflow running in Docker Compose.

The system implements a modern Medallion Lakehouse Architecture structured into three primary tiers:

  • BRONZE LAYER: Automated ingestion DAG extracting raw data from both an open REST API (Open-Meteo API) and a web scraping target (NASA LHASA portal directory scraping using BeautifulSoup4), persisting raw JSON files with ISO datetime nomenclature (source_YYYYMMDD_HHMMSS.json) in datalake_bronze/.
  • SILVER LAYER: An automated processing DAG triggered via an Airflow FileSensor that detects newly arrived Bronze JSON files, applies an end-to-end data cleansing and transformation pipeline (schema enforcement, null imputation, NLP text normalization, IQR/Z-score outlier detection, deduplication), and writes optimized Apache Parquet tables with embedded schema metadata in datalake_silver/.
  • GOLD LAYER (PLANNED): Analytical stage reserved for Workshop #3, where multi-temporal Parquet files will be aggregated across 0.25° spatial grid cells via PySpark to generate the Landslide Risk Indicator.

2.2 Technology Choices and Engineering Rationale

  • Pandas vs. Polars for Silver Processing: Pandas (version 3.1+) with PyArrow backend was chosen due to its comprehensive interoperability with geospatial libraries (rasterio, shapely) and mature integration with Airflow task decorators. For the current dataset sizes (thousands of hourly rows per batch), Pandas delivers sub-second execution while maintaining native support for categorical and UTC timestamp types.
  • Parquet vs. CSV / SQLite for Silver Persistence: Apache Parquet is a columnar binary format featuring Snappy compression and dictionary encoding. Parquet reduces storage by over 75% compared to raw JSON/CSV, allows column-pruning during Gold-layer PySpark queries, and retains embedded schema metadata and custom key-value lineage tags without requiring separate catalog tables.
  • LocalExecutor vs. CeleryExecutor for Docker Stack: In Docker on developer workstations, LocalExecutor provides multi-process concurrency directly managed by the Airflow Scheduler, eliminating the operational overhead, network latency, and memory footprint (~2.5 GB RAM savings) of additional Redis broker and Celery worker containers.

4. Preprocessing Pipeline Design & Empirical Justification

The transformation pipeline bridging the Bronze and Silver layers addresses the empirical data quality anomalies identified during the exploratory profiling in Workshop No. 1.

4.1 Cleaning and Transformation Stages

Stage Observed Issue in Workshop #1 Transformation & Imputation Strategy Enforced Silver Schema
1. Type Normalization Mixed timestamp formats; local Colombian times (UTC-5) lacking timezone indicators. All timestamps parsed with ISO 8601 strict format and converted to UTC (datetime64[ns, UTC]). Local times offset by +5h. timestamp: timestamp[us, tz=UTC], coordinates: float64.
2. Null Handling The catastrophic Mocoa landslide (2017) had country_name = NULL. Secondary metrics (soil moisture) contained sporadic missing values. Spatial bounding box filtering prevents dropping Colombian events with null country names. Missing soil moisture is imputed with the station median and flagged with soil_moisture_imputed = True. country_name: string (imputed 'Colombia'), soil_moisture_imputed: bool.
3. NLP Preprocessing Unstructured narrative descriptions in English and Spanish with accents, punctuation, URLs, and noise. Punctuation stripping via regex, Unicode accent normalization (NFD decomposition), lowercase conversion, bilingual stopword filtering, and tokenization into word arrays. cleaned_text_nlp: string, tokens_nlp: list<string>, token_count: int64.
4. Outlier Detection Tropical rainstorms generate extreme hourly precipitation spikes (> 50 mm/h) that could distort linear models if unflagged. Calculates Interquartile Range ($IQR = Q_3 - Q_1$, threshold $Q_3 + 1.5 \times IQR$) and standard Z-score ($|Z| > 3.0$). Flags outliers without dropping them, preserving vital hazard signals. precip_outlier_iqr: bool, precip_outlier_zscore: bool, precip_zscore: float64.
5. Deduplication Duplicate event reporting in disaster catalogs and repeated polling across overlapping weather windows. Deduplication using composite natural keys: (station_name, timestamp) for weather, and (nominal_issue_time, file_name) for LHASA. Natural primary key uniqueness enforced per file.
6. Lineage & Traceability Need to prove data provenance from Bronze files to Silver Parquet for auditability. Every row is tagged with the exact Bronze filename and processing timestamp, plus a deterministic SHA-256 content hash of the original fields. _bronze_source_file: string, _processed_at_utc: timestamp, _record_hash: string.

5. Airflow DAG Implementation Details

5.1 Bronze Ingestion DAG (bronze_ingestion_dag.py)

The ingestion DAG is developed using the modern Airflow TaskFlow API (@dag and @task decorators), ensuring clean parameter passing via XComs and avoiding legacy boilerplate operators.

  • DAG ID: bronze_ingestion_dag
  • Schedule: @hourly (configurable to cron 0 * * * *)
  • Tasks:
    1. extract_weather_api(): Queries Open-Meteo REST API for 10 high-risk Colombian monitoring stations (Bogotá, Medellín, Cali, Manizales, Pereira, Ibagué, Bucaramanga, Pasto, Mocoa, Villavicencio).
    2. extract_lhasa_scraper(): Connects to the NASA LHASA NRT hazard repository, scrapes the directory listing using BeautifulSoup4, parses GeoTIFF filenames and issue dates, and performs HTTP HEAD checks on recent files.
    3. extract_landslide_catalog(): Extracts Colombian historical landslide events from the NASA GLC inventory.
    4. validate_and_persist(): Runs structural schema checks (envelope validation, coordinate bounds check) and persists files in datalake_bronze/ following the convention {source_id}_YYYYMMDD_HHMMSS.json.

5.2 Silver Processing DAG with FileSensor (silver_processing_dag.py)

The Silver DAG is designed to react dynamically to incoming Bronze data:

  • FileSensor Operator: Uses FileSensor (fs_conn_id="fs_default") to monitor /opt/airflow/datalake_bronze. Configured with a poke_interval=15 seconds and timeout=300 seconds.
  • Downstream Transformation Task: process_bronze_to_silver() discovers all unhandled JSON files in the Bronze layer, checks against an idempotent manifest (.processed_manifest.json), executes the cleaning and NLP pipelines, and writes output files to datalake_silver/{topic}_YYYYMMDD_HHMMSS.parquet.
  • Idempotency Guarantee: Running the DAG multiple times over the same directory will not duplicate records; files previously processed are recognized via the manifest, and individual record hashes ensure deterministic outputs.

7. Challenges Encountered & Engineering Decisions

Technical Challenge Root Cause Engineering Resolution & Decision
Local Docker Resource Footprint The standard Airflow docker-compose template uses CeleryExecutor with Redis and worker containers, consuming over 4 GB of RAM. Configured LocalExecutor with PostgreSQL. Reduced idle container memory to ~1.2 GB while retaining parallel task execution and high stability on Windows/WSL2.
FileSensor Connection Setup in Airflow Airflow's FileSensor requires a filesystem connection (fs_default), which defaults to local paths that can fail if not explicitly mapped inside containers. Injected AIRFLOW_CONN_FS_DEFAULT: "fs:///opt/airflow/datalake_bronze" directly into the container environment variables, ensuring immediate out-of-the-box sensor operation without manual UI configuration.
Preserving Critical Hazard Outliers Standard data cleaning often clips or discards statistical outliers. In natural hazard monitoring, extreme precipitation events are the primary triggers of landslides. Implemented non-destructive outlier detection: extreme values are flagged via boolean masks (precip_outlier_iqr, precip_outlier_zscore) and quantified with Z-scores, rather than being deleted or Winsorized.
Border Coordinate Filtering The Colombian bounding box (lat [-4.3, 13.5], lon [-79.1, -66.8]) slightly overlaps northern Ecuador and western Venezuela. Combined bounding box filtering with conditional country logic: keep records where country_name == 'Colombia' or where country_name is null/empty but coordinates fall inside the box (recovering Mocoa), while explicitly excluding foreign labeled events.
